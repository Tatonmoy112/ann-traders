# Client security review - 31 October 2026

Scope: apps/client, its production dependencies, anonymous Supabase read boundary, related public SQL, request controls, formatting and deployment settings. This is a source review plus bounded local production tests and hosted anonymous zero-row probes, not a penetration-test certification.

## Query and authorization review

The listing RPC remains security invoker, with a pinned empty search_path. Its only formatted SQL fragments are an allowlisted identifier and a fixed asc/desc value; user values use bound USING parameters. Category/brand matching is exact; missing slugs produce no unfiltered fallback. Page sizes, page numbers and search/filter lengths are bounded. Media/pricing projection follows bounded identity selection.

Owner-evaluated security-barrier views intentionally preserve anonymous access without granting normalized tables. Published, undeleted products in active categories, active variants/current prices, public document metadata and ready public media define the projection. No client service-role fallback, inquiry insertion, private document signing, raw HTML injection, SQL string concatenation of filter values, cookie-based privilege or public upload API remains.

No new hosted migration or permission change was needed for this review. The database integration suite verifies anonymous read/write grants, draft/withdrawal filtering, malformed sort injection, price windows and incompatible pricing. A Supabase owner should still review exposed objects and role query timeouts directly; HTTP checks alone are not a complete database grant inventory.

## Evidence

- [Hosted checks](client-security-hosted.json): all 10 core/private objects returned 401 / SQL 42501 for anonymous zero-row SELECT; all 5 intended public projections returned 200. No hosted data was changed and no private records were retrieved.
- [Dependency audit](client-security-dependencies.json): zero known production dependency advisories after removing the client Axios dependency. The initial workspace production audit reported 34 advisories, all in Axios/follow-redirects.
- [Local production acceptance](client-security-runtime.json): nonce uniqueness/framework propagation, production script policy, security headers, no-store, invalid input/method rejection, purge authorization/origin/body checks, private-image optimizer rejection, browser hydration/search/XSS escaping, and a 429 burst test despite untrusted forwarded-header rotation.
- [Final check results](client-security-results.json): 143 tests pass across 11 files, including 57 real PostgreSQL tests, plus 30 production security checks and 21 production catalog checks. Client lint, typecheck, Prettier formatting and the isolated production build pass. Request tests cover trusted origins, spoofing, limits, CSP, native HTTP, image URLs and database transport. Existing admin lint findings from the earlier remediation are outside this client review.
- No remote load test, automated password rotation, active Vercel WAF configuration, provider-wide distributed quota, or hosted HTTPS security-header certification is claimed.

## Operational limits

The application limiter is best-effort per process. Vercel WAF must be activated and verified before production; its counters are regional. Its 240 requests/minute/IP baseline should be adjusted using actual buyer/NAT traffic. Request-body buffering is capped at 1 KB in Next Proxy; this limits cloning memory and does not replace the hosting ingress limit. Application code rejects bodies for the only POST route.

CSP allows inline styles, but scripts require a fresh nonce. Existing immutable R2/CDN files and browser/prefetch/downloaded copies cannot be recalled by application authorization. Publication visibility is a fresh request-time check, not an atomic lock spanning a concurrent withdrawal. The signed outbox receiver with durable replay/revision tracking remains the earlier remediation MVP's documented production acceptance gap.

The hardcoded hosted database password requires owner rotation. The retired helper previously applied obsolete raw anonymous table grants, so it is intentionally not an executable deployment shortcut.

No security mechanism guarantees absence of vulnerabilities. Preserve dependency monitoring, access review and deployment verification as the app evolves.
