## Database compatibility and safety

Preserve the 28 public core tables, product/variant FKs, existing media IDs/order/primary flags, all existing Images rows and URLs, audit records, public projection field names, and PDF bucket/functions. Add media metadata and private control functions only. Permit both legacy `cloudflare_images` and new `r2` records; new uploads use R2 exclusively. Disable legacy stage/attach capabilities after the refactor so unverified legacy attachment is not an alternative upload path. Legacy pending uploads must be restarted under R2. Existing ready media remains usable and replaceable.

Retirement replaces destructive media-row deletion. Replacement records link back to old media and inherit placement only when verified attachment commits. Cleanup events contain provider-qualified, server-owned keys; retained history does not count as an active reference. Verification leases and cleanup claims prevent attachment/deletion races. Record every proposed public key before writing it so interrupted promotions remain recoverable.

## Storage design and tradeoffs

Use separate private staging and custom-domain public delivery buckets. Browsers receive a five-minute PUT capability for one generated staging key; sign content type, length and `If-None-Match: *`. Presigned URLs are bearer capabilities, not inherently single-use: conditional writes prevent overwriting a successful first PUT, including concurrent PUTs. Keep staging objects until after URL expiry and a safety delay, so deleting a staging object cannot reopen that capability prematurely. Also configure a short staging lifecycle as a provider-side backstop.

Never copy an untrusted original to the public bucket. Verify actual size, declared MIME and magic, dimensions, animation/page count, and a full Sharp decode; generate metadata-stripped WebP images from the exact verified buffer. Public output keys include a unique verification attempt, are immutable, and never share a key with staging. Promotion happens before the DB ready transition; failed/abandoned outputs remain in a recorded manifest for retry cleanup. A verified image can be publicly retrievable before product publication; draft catalog records remain private, and publication still requires ready primary media. Already downloaded public bytes cannot be revoked by database visibility alone.

No production infrastructure, CORS policies, buckets, domains, remote schema, or data will be changed in this task. Local migration/SQL and provider-double tests will be used; real R2/CORS/CDN verification remains an explicit staging release gate when credentials/infrastructure are available.
