# R2 image lifecycle

New uploads use AWS SDK v3 and Cloudflare R2; existing Cloudflare Images URLs remain supported until explicitly migrated. Supabase private PDF storage is unchanged.

1. Authenticated POST `/api/admin/images/create-upload` checks claims/current role/MFA, exact origin and bounded Zod payload. The service-only `r2_create_upload` locks the draft, verifies revision/replacement target, applies an actor quota and creates a pending media/session row. Generated keys never contain a filename. Session records pin bucket names and CDN origin.
2. Server signs a 300-second PUT for the private staging bucket with the exact Content-Type, Content-Length and `If-None-Match: *`. Browser uploads the raw File, with progress/cancel. Presigned URLs are bearer capabilities, not intrinsically one-time tokens. R2 atomically evaluates the conditional header, so at most one concurrent first PUT succeeds. Repeated PUT cannot alter the stored bytes. Staging objects remain until URL expiry plus a ten-minute margin; otherwise early deletion would reopen a still-valid PUT capability.
3. Authenticated POST `/api/admin/images/complete-upload` checks uploader/product and acquires a five-minute verification lease. A second verifier conflicts. The server streams the exact private object, bounds bytes, checks stored length/type and magic, reads dimensions/pages, and fully decodes/re-encodes using Sharp. Invalid SVG/HTML, corrupt files, unsupported declarations, oversized/tiny images and supported animated/multipage formats are rejected. Untrusted originals never enter the public bucket.
4. Generate WebP outputs inside 320/768/2000px bounding boxes without enlargement, strip metadata, and hash original/outputs. Keys include product UUID, media UUID, verification token and size name. `r2_plan_promotion` records all planned keys before any public writes. Public PUTs are conditional: development uses `no-store`; production uses `public, max-age=31536000, immutable`.
5. After all three writes succeed, service-only `r2_finish_upload` rechecks active actor, draft revision, ownership and lease, marks the row ready, and increments product revision atomically. Repeated completion returns success without another mutation. Concurrent edit/detach invalidates attachment; the durable cleanup event recovers any written outputs. No client supplies a verified URL or an arbitrary object key.
6. Replacement retires the old row only in the successful attach transaction and inherits its primary/order/variant/alt placement. Detach retires rather than hard deletes. Historical rows, IDs, provider references and audit records remain intact. Primary/alt/order mutations retain the existing authorization and revision checks.
7. Every session creates a delayed outbox recovery task. Retirement also creates a provider-aware task. `r2_prepare_cleanup` refuses active capabilities/leases, fences abandoned verification, retains active ready public objects, and excludes live references. It returns only exact server-recorded keys. Worker deletes eligible objects, purges their exact CDN URLs, then removes staging. Failure retries with existing outbox backoff/dead-letter rules. Repeated deletes/purges are safe. Missing purge configuration fails visibly instead of acknowledging incomplete revocation.

## Public delivery

Set `R2_PUBLIC_BASE_URL` to the public bucket's real HTTPS `r2.dev` origin for local development. Explicit `R2_ENVIRONMENT=development` requires loopback `APP_ORIGIN`; explicit `R2_CDN_PURGE_MODE=disabled` skips the CDN API only for uncached development delivery. Staging must never expose a public URL or custom domain. HTTPS and normal certificate validation remain mandatory. See [local setup](../operations/local-r2-development.md).

Production defaults to `R2_ENVIRONMENT=production` and `R2_CDN_PURGE_MODE=cloudflare`; use a dedicated HTTPS custom domain and disable its public development URL before launch. Disabled purge or r2.dev delivery is rejected in production mode. Use generated WebP variants, not Images hosted variants or an unrestricted transformation endpoint. Public projections retain `image_url` and append `image_key`; each `image_variants` entry includes its canonical key. No staging keys are exposed. Existing Images records retain their URLs and have no R2 key.

Stored object keys are canonical. Admin responses resolve URLs from the current configured origin without mutating history; public consumers join their configured delivery origin with `image_key` / variant `key`. Existing URL fields are compatibility hints. Domain cutover requires no image upload or key change. Wait for pending upload sessions to finish/expire, list former recorded origins in `R2_PREVIOUS_PUBLIC_BASE_URLS`, and keep the same buckets. Cleanup accepts only those explicitly trusted origins, deletes by canonical key, and purges current/former custom-domain URLs. Previous r2.dev origins have no Cloudflare CDN cache. Cross-domain category/brand references remain protected by key suffix. Former custom domains in another zone require a separately reviewed purge strategy.

Immutable URLs are never overwritten. Replacements get new keys. Normal catalog cache invalidation remains product lifecycle based; cleanup performs exact-file purge when an object is retired. Purge success is required before cleanup acknowledgement. Browser caches/downloaded copies cannot be recalled; a database unpublish alone cannot make an already-public image private. Image visibility and sensitive-document visibility have different contracts: PDFs remain access-authorized in private Supabase Storage.

## Rollout and limitations

Review `r2-impact-assessment.md`, review migrations 012–014 after the existing baseline, configure the environment-specific delivery/purge settings, then verify real provider and worker behavior. Migration 013 includes pinned cleanup bucket names; 014 exposes public keys and protects references across domain changes. An empty hosted schema needs the complete 001–014 chain after approval. Do not reset the schema. Old ready media and legacy cleanup are preserved; old pending Images uploads must restart. No automatic bulk transfer or destructive removal of existing Images assets occurs.

Actual R2 infrastructure, custom domain, CDN cache rules, lifecycle rules and worker scheduling were not created or changed by this refactor. Local S3/Supabase doubles and real PostgreSQL tests cover behavior; they are not proof of hosted CORS, IAM or CDN configuration. Pin bucket/domain configuration or drain/migrate recorded sessions before changing it. See `infra/r2/README.md` and the operations runbook.
