# Local Supabase + R2 development

Use the private `ann-traders-uploads-private` staging bucket and public `ann-traders-product-images` bucket. Staging must have Public Development URL disabled and no custom domains. Enable the public bucket's development URL only, and use the exact HTTPS `pub-…r2.dev` origin as `R2_PUBLIC_BASE_URL`. Never use the S3 API endpoint for public delivery. There is no local custom-domain requirement and no TLS exception.

The local environment is configured with `R2_ENVIRONMENT=development`, `R2_CDN_PURGE_MODE=disabled` and `APP_ORIGIN=http://localhost:3000`. Disabling purge requires explicit development mode, a loopback admin origin and uncached development delivery. New generated WebP objects carry `no-store`. Missing mode defaults to production, where development delivery and disabled purge are rejected. No zone ID or purge token is required locally.

Apply [the local staging CORS policy](../../infra/r2/staging-cors.local.json) to the private staging bucket only. Both localhost origins are listed explicitly; requests from other origins are rejected. Browser PUT includes content type and the write-once precondition; Content-Length is generated by the browser. Do not add public access, wildcard origins or wildcard headers to fix CORS. Keep restricted bucket credentials server-only.

## Start the local stack

Docker must be running. The local Supabase project ID is `ann-traders-local`. All migrations through 014 apply when creating the local stack. Public signup remains disabled globally. The email provider toggle is enabled so invited email/password users can sign in; the verification script checks that unauthenticated signup is still rejected. Auth MFA/RBAC rules remain unchanged.

```powershell
pnpm.cmd db:start
# Capture generated settings without displaying local keys:
New-Item -ItemType Directory -Path .local-r2 -Force | Out-Null
pnpm.cmd exec supabase status -o json 2> .local-r2/supabase-status-error.log |
  Out-File .local-r2/supabase-status.json -Encoding utf8
node --experimental-transform-types scripts/configure-local-r2.mjs --supabase
pnpm.cmd dev
```

The configurator preserves unrelated local entries, normalizes duplicate canonical setting lines, uses the actual public development URL already supplied, and writes ignored local app/worker environment files. It never copies hosted credentials into the canonical local Supabase variables. The local Supabase database URL is checked for loopback before use.

In separate terminals run the local worker handler and scheduler:

```powershell
pnpm.cmd media:functions:local
pnpm.cmd media:worker:local
```

The handler uses `CATALOG_WORKER_SECRET` even though gateway user-JWT verification is disabled. The scheduler refuses non-loopback Supabase targets and polls every 15 seconds. Missing catalog invalidation receivers still retry using existing outbox semantics; this command does not silently acknowledge them. These commands never deploy or schedule a hosted worker.

Each staging capability expires after five minutes. Cleanup runs only after expiry plus ten minutes and after verification leases are clear. Detach/replacement retires rows and queues cleanup; it does not bypass that delay. Failed/aborted uploads also have durable recovery tasks. Do not shorten the guard or delete staging early to speed up development tests. A one-day private staging lifecycle remains the provider-side outage backstop.

## Verify and review

```powershell
node --experimental-transform-types scripts/inspect-r2-config.mjs
node --experimental-transform-types scripts/verify-local-r2.mjs
```

The explicit integration runner creates an invited editor in **local** Supabase, signs into the real admin in Chromium, uploads isolated test images to R2, verifies public generated images, rejects invalid content and unauthorized requests, retires media, waits out the safety window and invokes the real local Edge cleanup worker. Local test media/audit history remains for inspection; R2 test objects must return authenticated 404 after cleanup. Generated local test-user credentials are in ignored `.local-r2/local-r2-user.json`, never in committed reports. Settings, credentials and recovery journals stay outside Playwright's cleared output directory. Re-running generates a new local fixture and isolated keys.

The admin is at `http://localhost:3000`. A runtime serving R2 requests needs outbound network permission; a restricted development process can sign URLs without being able to read or promote objects. Grant runtime network access normally; do not disable certificate validation or proxy image bytes through an insecure endpoint.

## Future domain cutover

Keep the same buckets and canonical object keys. Drain pending sessions, configure the real HTTPS custom domain, update `R2_PUBLIC_BASE_URL`, add former origins to `R2_PREVIOUS_PUBLIC_BASE_URLS`, switch to production/cloudflare modes, configure purge credentials, and restart/rebuild CSP as appropriate. Admin URLs resolve from keys. Public consumers must use `image_key` / variant `key` with their configured origin rather than treating stored URL hints as identifiers. No image upload or filename migration is required. Hosted migrations and infrastructure changes need separate approval.
